1. System Architecture Overview

The system is built on modern GitOps principles where Git is the single source of truth. The Kubernetes cluster never exposes inbound deployment ports; instead, ArgoCD continuously reconciles cluster state against Git.

2. The 12-Factor App & Kubernetes Probes

A. Decoupled Configuration (12-Factor Factor III)

Never hardcode hostnames like localhost:6379. In Kubernetes, services get internal cluster DNS names injected via environment variables.

# In redis_cache.py
REDIS_HOST = os.getenv("REDIS_HOST", "localhost")
REDIS_PORT = int(os.getenv("REDIS_PORT", "6379"))

Probe Endpoint Question it Answers Action on Failure
Liveness Probe /healthz Is the Python process alive or deadlocked? Kubelet kills and restarts the container.

3. Production Docker Hardening

A. Non-Root Execution (Security Standard)

By default, Docker containers run as root (UID 0). In production Kubernetes, running as root is a major security vulnerability (PodSecurityStandards violation). We explicitly configure an unprivileged user:

RUN groupadd -g 1000 appgroup && useradd -u 1000 -g appgroup -s /bin/bash -m appuser
USER appuser

B. Docker Layer Caching with uv

Dependencies change much less frequently than application code. We install external wheels first without the project code, taking full advantage of layer caching:

# Step 1: Copy lockfiles & install dependencies (Cached layer)
COPY pyproject.toml uv.lock README.md ./
RUN uv sync --frozen --no-dev --no-install-project

# Step 2: Copy source code and perform fast local install
COPY --chown=appuser:appgroup src/ ./src/
RUN uv sync --frozen --no-dev

4. Helm Packaging & Templating

Why Helm?

Helm provides variable templating, versioning, and environment-specific overrides (values-dev.yaml vs values-prod.yaml).

Chart Structure

helm/ml-serving-capstone/
├── Chart.yaml              # Chart metadata (name, version)
├── values.yaml             # Defaults: replicas: 2, image: v0.1.0, resources
└── templates/
    ├── deployment.yaml     # Pod template with probes and securityContext
    ├── service.yaml        # ClusterIP routing
    ├── configmap.yaml      # Dynamic environment variables
    ├── redis.yaml          # In-cluster Redis deployment
    ├── kafka.yaml          # In-cluster Kafka broker (KRaft mode)
    └── hpa.yaml            # Horizontal Pod Autoscaler

5. GitOps & ArgoCD in Depth

Push vs. Pull (GitOps) Model

Feature Traditional Push (Jenkins/GitHub Actions) GitOps Pull (ArgoCD)
Cluster Credentials CI holds admin kubeconfig (High Risk) CI never touches cluster; ArgoCD lives inside (Zero Trust)
Config Drift Manual changes with kubectl stay forever Self-Healing: Reverts manual tampering within seconds
Rollbacks Re-running complex deployment pipelines Single git revert commit in Git

The Declarative ArgoCD Manifest (argocd/application.yaml)

apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: ml-serving-capstone
  namespace: argocd
  finalizers:
    - resources-finalizer.argocd.argoproj.io # Cascading deletion
spec:
  project: default
  source:
    repoURL: 'https://github.com/mastershantash/project-one.git'
    targetRevision: main
    path: ml-serving-capstone/helm/ml-serving-capstone
    helm:
      valueFiles:
        - values.yaml
  destination:
    server: 'https://kubernetes.default.svc'
    namespace: ml-serving
  syncPolicy:
    automated:
      prune: true     # Deletes pods if deleted from Git
      selfHeal: true  # Corrects unauthorized manual kubectl edits
    syncOptions:
      - CreateNamespace=true

6. Production Logging with Splunk

How Kubernetes Ships Logs to Splunk

In Kubernetes, applications write structured JSON to stdout. The container engine writes these to /var/log/pods/ on the host node.

A log forwarder (like Fluent Bit) runs as a DaemonSet (one pod per node), tails those log files, attaches Kubernetes metadata (namespace, pod name, container name), and posts them via HTTP Event Collector (HEC) to Splunk on port 8088.

8. Self-Quiz & Review Checkpoints

Quick Test Your Knowledge:

  1. Why do we separate Liveness and Readiness probes?
    Answer: If a model takes 30 seconds to load, a liveness probe might prematurely kill the pod thinking it's deadlocked. A readiness probe simply isolates the pod from traffic until it finishes loading.
  2. What happens when someone manually deletes a deployment with kubectl delete when ArgoCD selfHeal: true is active?
    Answer: ArgoCD detects that the live cluster state deviates from the Git repository and instantly recreates the deployment to match Git.
  3. Why do we run containers as UID 1000 instead of root?
    Answer: If an attacker exploits a vulnerability in the application (like a remote code execution in a Python library), they are trapped as an unprivileged user and cannot compromise the host kernel.
